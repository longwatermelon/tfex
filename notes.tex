Note: this is only one construction on how \textit{you} could discover transformers. I chose this construction because it's highly clean and simple, so it's built on steadier common-sense foundations which you understand every part of. \\

But ultimately, transformers are an engineering problem; there's no ``correct'' way to ``derive'' them.

\section{Problem}

You have $T$ objects $1,...,T$ with numerical representations $x_1,...,x_T \in \bbr^d$. You want to compute something about these objects based on complex interactions between the objects.

\section{Message passing}

The obvious idea is learning a function $f(x_i,x_j)$: ``what info should $x_i$ pass to $x_j$?''. It's of type $f : (\bbr^d,\bbr^d) \rightarrow \bbr^d$. \\

If $x'_j \in \bbr^d$ is object $j$ plus info it received, then
\[ x'_j = x_j + \sum_{i=1}^T f(x_i,x_j) \]

We can use an MLP to implement $f$ or something similar. \\

A single message-passing round is limited to pairwise interactions (our model is simplistically pairwise with only $f(x_i,x_j)$; interactions of $>2$ objects is limited to additive ``interaction''). So just run multiple rounds of message-passing to get over this. \\

Final algo:
\1 Let $x_1,...,x_T \in \bbr^d$ be our initial object reprs.
\1 For each $\mathrm{round}=1 \rightarrow N$:
\2 For each $j=1 \rightarrow T$:
\3 $x'_j := x_j + \displaystyle \sum_{i=1}^T f(x_i,x_j)$
\2 For each $j=1 \rightarrow T$:
\3 $x_j := x'_j$
\0

\section{The transformer (aka: optimized message passing)}

Our message-passing algo is $O(T^2)$ MLP calls; inefficient. \\

Hypothesis: we can do complex feature-engineering outside of the message-passing loop (in less than $O(T^2)$ time), and our $O(T^2)$ message-passing loop can become cheaper. \\

Implementation: we split the rounds into two steps.
\1 \textbf{Step 1}: Complex feature-engineering. For each $x_j$, do $x_j := x_j + \text{MLP}(x_j)$. (This is $O(T)$ with high const factor.)
\1 \textbf{Step 2}: Message-passing.
\2 In standard transformers, each object $i$ broadcasts \textit{one} message $v_i$ and object $j$ scores how much it wants $v_i$.
\3 Broadcasted message usually computed as $v_i = x_i W_V$, shape of $W_V$ is $[d,d]$.
\3 Score usually computed $s(x_i,x_j) = k_i \cdot q_j$ where $k_i = x_i W_K$ and $q_j = x_j W_Q$ ($W_K,W_Q$ shape $[d,d_k]$).
\2 So we use $f(x_i,x_j) = s(x_i,x_j) v_i$: a dot-product and then scaling $v_i$ with it, which is much lower const factor than prev MLP def of $f$.
\2 We call this modified message-passing \textbf{attention}. This is $O(T^2)$ with low constant factor (dot-product and vector scaling, all within $O(d)$ flops).
\\\0

Multi-head attention is a compromise between \textbf{single-message broadcast} ($x_i$ broadcasts one message $v_i$) and \textbf{$T$-messages broadcast} ($x_i$ broadcasts $T$ messages $\text{MLP}([x_i,x_1])$, ..., $\text{MLP}([x_i,x_T])$). Instead, use a fixed number of $h$ heads (some fixed small $h \ll T_{max}$), where each head does a single-message broadcast.
\1 Hypothesis: $\text{MLP}([x_i,x_j])$ only takes on a few distinct directions across all $1 \le j \le T$, so MHA approaches $T$-messages broadcast's perf close enough.
\1 Implementation: each head $1 \le m \le h$ gets $W^{(m)}_Q,W^{(m)}_K,W^{(m)}_V$ (so receiver objects $j$ can also query for different things depending on what $i$ is broadcasting).
\0

\section{Polishing the transformer}

Transformers usually have an embedding module before the $N$ message passing rounds. Embedding module produces the initial $x_1,...,x_T \in \bbr^d$ vectors.
\1 Benefit: embedding module can figure out useful features for first attn round. First MLP thus becomes redundant. Swap the order of attention and MLP. It goes embedding $\longrightarrow$ $\overset{\times N}{\text{(attn $\longrightarrow$ MLP)}}$ instead of $\overset{\times N}{\text{(MLP $\longrightarrow$ attn)}}$.
\\\0

Softmax normalizes qk-dot values and also helps attention concentrate more easily; increasing one logit's value moderately can sharply shrink the rests' prob mass once passed through softmax. Previous $s(x_i,x_j)$ dot product def is used as logits for actual attention's softmax, so the weight on $v_i$ is
\[ \alpha_{ij} = \frac{e^{s(x_i,x_j)}}{\sum_{i'=1}^T e^{s(x_{i'},x_j)}} \]
and the update becomes $x'_j = x_j + \displaystyle \sum_{i=1}^T \alpha_{ij} v_i$.

\section{Other misc. notes on why transformers}

Bitter lesson: general architecture with massive scale wins. Transformers are highly general (just fast message-passing). \\

LLMs are also \textit{easy} to scale because next-token prediction as a task is parallelizable on the transformer arch (let $x'_j$ be prediction of token $j+1$ for context $x_1,...,x_j$, and with causal masking, you have $T_{max}$ examples running in parallel).
